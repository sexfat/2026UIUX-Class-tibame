Mindset

從一張好看的頁面
到一套產品系統

頁面一多，改一次品牌色就要改上百個地方。這個單元要練的，是讓每個設計決策只存在一個地方。

  • 單一真相來源：顏色、間距、元件都只定義一次，其他地方全部「引用」它
  • 前端元件化思維：設計師怎麼拆圖層，工程師就會怎麼寫結構
  • 按下 Create Component 讓圖層變紫色只是開始，背後的架構邏輯才是重點

Tokens 03 · In Figma

Figma Styles 與 Variables 怎麼分工？

Figma StylesFigma Variables
適合存什麼多層疊加的效果：陰影、漸層、多重填色、完整的文字樣式組合單一數值：顏色、數字（間距、圓角、尺寸）、字串、布林值
多模式切換不支援支援 Mode：Light / Dark、品牌 A / B、桌機 / 手機
可以綁定到填色、文字、效果（Effect）填色、間距、圓角、寬高、文字內容、圖層顯示與隱藏
可以互相引用Style 可以使用 Variable 的值Variable 可以指向另一個 Variable（就是兩層式命名）
對應到前端一組 CSS 樣式（例如 box-shadow 疊多層）CSS Custom Properties（--btn-primary-bg）
判斷原則：一個值就說得完的用 Variables；需要好幾層疊在一起才成立的用 Styles。

Components 02 · Inheritance

母元件與實例：繼承與覆寫

Main Component → Instance
◆ Main Component · Button送出
↓↓↓
◇ Instance送出沒有覆寫
◇ Instance送出沒有覆寫
◇ Instance立即預約文字已覆寫
修改母元件的…沒覆寫的實例覆寫過文字的實例
背景色跟著變跟著變
文字「送出」→「確認」跟著變保留「立即預約」
  • 改母元件，所有實例同步更新：這就是單一真相來源在元件上的實現。
  • 實例可以覆寫（Override）：在實例上改過的文字或顏色，那個屬性就會被鎖定，之後母元件再改同一個屬性也不會蓋掉它。
  • 只鎖改過的那一項：沒動過的屬性，仍然繼續跟著母元件更新。
  • 想回到母元件的樣子，在實例上使用 Reset all changes。

System 03 · Documentation

元件說明文件：寫出「什麼時候用」

範例：Radio Button 還是 Dropdown？
✓ Do 諮詢方式
選項 2–5 個、需要一眼比較時，用 Radio 全部攤開。
✕ Don't 是否需要發票
請選擇▾
只有 2 個選項卻藏進 Dropdown，使用者要多點一次才看得到。選項超過 7 個（例如縣市）才適合用 Dropdown。

每個元件的說明至少要寫：

  • 使用時機：什麼情境該用這個元件
  • 不該使用的時機：以及應該改用哪個元件
  • Do / Don't 對照圖：用畫面說明，比文字更快懂
  • 無障礙：鍵盤操作、Focus 樣式、對比度
  • 文案原則：按鈕用動詞開頭、錯誤訊息要說怎麼修正

交付：這些先避開

元件庫只有元件本體，完全沒有使用說明 每個元件旁邊附上「何時用 / 何時不用」與 Do / Don't 對照，例如 Radio 與 Dropdown 的選擇規則。
圖層用手動擺放，沒有使用 Auto Layout 工程師無法從圖層推斷結構，文字一變長就破版。元件與區塊都用 Auto Layout，並設定好 Hug / Fill / Fixed。
只交付 Default 狀態的畫面 Hover、Focus、Error、Loading、無資料要讓工程師自己猜。交付時附上狀態矩陣與邊界案例（長文字、空狀態）。
交付前自問：如果我明天請假，工程師只看這份檔案，能不能把元件正確做出來？

Summary

本堂小結

  • 設計決策存成變數：Primitive 描述「是什麼」，Semantic 描述「用在哪」，深色模式靠語意層切換

  • Tokens ＋ 元件庫 ＋ 說明文件三者都要有，Auto Layout 就是寫給工程師的結構
